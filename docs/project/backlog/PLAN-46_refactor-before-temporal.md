1) Move executable/spec assets out of docs/ (most important)

Why: docs/ is your knowledge graph and narrative index. Keeping executable assets there creates drift and policy exceptions over time.

Actions
	•	Move workflow specs:

git mv docs/workflows examples/workflows


	•	Move Temporal bridge:

mkdir -p adapters
git mv docs/temporal_worker adapters/temporal-worker


	•	Move JSON schemas:

mkdir -p contracts/schemas
git mv docs/SPECS/* contracts/schemas/
rmdir docs/SPECS || true



Update references (README, PLAYBOOK, tests):

# GNU sed (Linux); on macOS use gsed or 'sed -i ""'
rg -l 'docs/workflows' | xargs sed -i 's#docs/workflows#examples/workflows#g'
rg -l 'docs/temporal_worker' | xargs sed -i 's#docs/temporal_worker#adapters/temporal-worker#g'
rg -l 'docs/SPECS' | xargs sed -i 's#docs/SPECS#contracts/schemas#g'

Acceptance
	•	cargo test stays green after path updates.
	•	All docs examples use examples/workflows/*.yaml.
	•	uv run --project adapters/temporal-worker ... still works (README updated).

2) Freeze contracts: make generated snapshots first‑class

Why: Your CLI guarantees stable JSON envelopes; the repo should reflect this with explicit, versioned snapshots and an automated regeneration command.

Actions
	•	Add contracts/README.md explaining provenance and how to regenerate:

# Contracts (Snapshots)
Generated by: `nexoscli dev schemas export --out contracts/schemas`
Do not hand-edit. CI will fail if drift is detected.


	•	Add a justfile (or Makefile):

regen-schemas:
	nexoscli dev schemas export --out contracts/schemas

verify-schemas:
	@diff -ru contracts/schemas <(nexoscli dev schemas export --out -) || \
	(echo "Schema drift; run 'just regen-schemas'"; exit 1)


	•	Introduce semantic versioning per schema file name (you already do v0.2, v0.3): bump only when breaking.

Acceptance
	•	Running just regen-schemas (or make regen-schemas) is idempotent.
	•	CI job fails on drift (see §6).

Migration helper: quick, safe script

If you want a one‑shot helper, this bash script (Linux + GNU sed) performs the moves and most path rewrites:

set -euo pipefail

mkdir -p examples/workflows contracts/schemas adapters

# 1) Moves
git mv docs/workflows examples/workflows
git mv docs/temporal_worker adapters/temporal-worker
mkdir -p contracts/schemas
if [ -d docs/SPECS ]; then git mv docs/SPECS/* contracts/schemas/ || true; rmdir docs/SPECS || true; fi

# 2) Rewrite references
for pat in \
  's#docs/workflows#examples/workflows#g' \
  's#docs/temporal_worker#adapters/temporal-worker#g' \
  's#docs/SPECS#contracts/schemas#g'
do
  rg -l 'docs/workflows|docs/temporal_worker|docs/SPECS' | xargs -r sed -i "$pat"
done

# 3) Touch README stubs
[ -f contracts/README.md ] || cat > contracts/README.md <<'EOF'
# Contracts (Generated Snapshots)
Generated by `nexoscli dev schemas export --out contracts/schemas`.
Do not hand-edit; CI enforces drift-free snapshots.
EOF

echo "Migration complete. Review changes, run tests, fix any missed paths."

Why these are the most effective moves
	•	High leverage: One directory move (+ guardrails) removes the root cause of drift (code inside docs) and applies to all future work.
	•	Low risk: No behavior changes to CLI or plugins; we’re only changing file locations and adding CI checks.
	•	Scalability: Clear module boundaries (core, plugins, adapters, examples, contracts) match the mental model you want for the Temporal agent and beyond.
	•	Observability preserved: Nothing here touches the event pipeline; in fact, it reinforces it (write fences + contract snapshots).
	•	Contributor UX: With a justfile, CODEOWNERS, and structure checks, newcomers can be productive and safe in minutes.
