# NEXOS – Cline Operating Rules (v0.2)

**Purpose**: Keep changes scoped, deterministic, and observable. Follow these rules exactly.

---

## 0) Pre‑flight (always run first)

1. Run init + doctor (required checks):
   ```bash
   nexoscli dev init --yes
   nexoscli dev doctor --ci --checks graph,plugins,config,events,tools --require plugins,graph

If any required check fails: stop and report.
	2.	Read contracts + surface:
	•	Open docs/contracts/HELP_TOP.txt
	•	Open docs/contracts/TOOLS.json
	•	For the target plugin, open docs/contracts/HELP_<PLUGIN>.txt if present.
	3.	Identify scope label for this task (ask if not provided). Examples in .clinerules/scope.json:
	•	task-plugin, dev-plugin, observability, replay, cline-ingest

❗ Never rename commands/flags or change required/optional status without an ADR.

⸻

1) Allowed edit surface (respect the scope fence)

Only edit files matching the task’s allowed globs in .clinerules/scope.json.
If you need to go beyond: open a change proposal and wait.

Protected files (no edits without ADR):
	•	docs/contracts/** (snapshots)
	•	nexoscli-core/src/{envelope.rs,event.rs,plugin.rs,engine.rs}
	•	nexoscli-bin/src/main.rs (except automated plugin registration by dev plugin new --register)
	•	Any file with the header // generated by nexoscli dev plugin new

⸻

2) Generators before hand‑rolled
	•	New plugin or missing files → must use:

nexoscli dev plugin new --name <short-name> --register --yes


	•	Structure fixes:

nexoscli dev plugins check --fix-readmes



Do not hand‑roll crates or registries.

⸻

3) Task context & observability
	•	Create a task and make it active before edits:

nexoscli task new   --title "<short goal>"
nexoscli task start --task TASK-YYYYMMDD-<slug>

All commands will be tagged with {task_id, stage, session_id} in events.

	•	While working:
	•	Use ctx.ok/ctx.err patterns when touching command surfaces so events emit.
	•	Prefer end‑to‑end tests in nexoscli-bin/tests/ that assert JSON envelopes.
	•	Context switch:

nexoscli task pause     # clears session
nexoscli task resume --task <id>  # starts new session_id


	•	Finish:

nexoscli task end
nexoscli task bundle --task <id> --out ./bundle.tgz



⸻

4) Contracts & snapshots (no drift)
	•	After changes, rebuild docs & tool specs:

nexoscli dev docs build


	•	Do not hand‑edit generated files:
	•	docs/CLI_REFERENCE.md (generated)
	•	docs/contracts/** (snapshots maintained by CI)
	•	If command names/flags changed or help/schema differs from snapshots:
	•	Create/attach an ADR (docs/ADRs/ADR-YYYYMMDD-*.md)
	•	Update snapshots via the dedicated “update snapshots” PR.
	•	Otherwise: revert to match snapshots.

⸻

5) Tests (E2E first)
	•	Put new end‑to‑end tests under nexoscli-bin/tests/.
	•	Keep each test: arrange → act (CLI) → assert envelope.
	•	Run:

cargo test --workspace


	•	Ensure telemetry covers the run:

nexoscli dev telemetry report --since 24h



⸻

6) Cline ingest (optional when not in Dev Container)
	•	Locate storage (or set NEXOS_CLINE_STORAGE):

nexoscli cline locate
nexoscli cline import --since 7d --dry-run
nexoscli cline import --since 7d


	•	Imported tasks appear under .nexoscli/cline/tasks/ and are bundled with task bundle.

⸻

7) Commit & PR hygiene
	•	Conventional commits, reference Task ID:
	•	feat(task): add telemetry report (TASK-20250902-telemetry)
	•	If contracts changed: include ADR id in title:
	•	feat(task): add --name flag (ADR-20250902-task-start)
	•	Keep diffs ≤ ~300 LOC or ≤ 6 files.

⸻

8) Things you MUST NOT do
	•	❌ Edit protected files without ADR (see above).
	•	❌ Add cross‑plugin dependencies in Cargo.toml (plugins depend only on nexoscli-core + allowed libs).
	•	❌ Write secrets to repo—respect .nexoscli/redact.yaml patterns; redact outputs in tests.
	•	❌ Bypass ctx.ok/ctx.err when emitting results.

⸻

9) Quick self‑check loop (run before finishing)

cargo build --workspace
cargo test  --workspace
nexoscli dev plugins check
nexoscli dev doctor --since 24h --task-coverage-min 0.3
nexoscli dev telemetry report --since 24h

If any command fails: stop and fix. If scope violation is required: open a change proposal.

⸻

10) Help index
	•	CLI contract snapshots: docs/contracts/
	•	Engineering playbook: docs/PLAYBOOK.md
	•	Task bundles: nexoscli task bundle --out <dir|.tgz>

---

## 2) `.clinerules/scope.json` — **Scopes → allowed globs**

> Cline uses this to keep changes inside the task’s sandbox.

```json
{
  "version": "0.2",
  "scopes": {
    "task-plugin": [
      "plugins/task/**",
      "nexoscli-bin/tests/**",
      "docs/**",
      "scripts/ci/**"
    ],
    "dev-plugin": [
      "plugins/dev/**",
      "nexoscli-bin/tests/**",
      "docs/**",
      "scripts/ci/**"
    ],
    "replay": [
      "plugins/replay/**",
      "nexoscli-bin/tests/**",
      "docs/**"
    ],
    "cline-ingest": [
      "plugins/cline/**",
      "nexoscli-bin/tests/**",
      "docs/**"
    ],
    "observability": [
      "nexoscli-bin/src/**",
      "nexoscli-core/**",
      "nexoscli-bin/tests/**",
      "docs/**"
    ]
  }
}
